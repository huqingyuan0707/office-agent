# 功能进度总表（office-agent）

> 口径：需求唯一事实源 = `智能办公Agent 产品需求文档.md`（PRD）；本表**逐条对账** PRD 功能项与仓库实现，
> 状态只有三档：**✅ 已完成** / **🟡 部分完成（附边界）** / **⛔ 未做（附原因）**。
> 「证据」列给的是可核对的东西：工具名 / 端点 / 单测 / HTTP 冒烟脚本，不写「应该没问题」。
> §4 是**有序缺口清单（Backlog）**，按 P0 → P2 排序；每项做完后回填 §2 状态与 §5 验证记录。
> 维护规则见 §6。

## 1. 怎么读这张表

| 档位 | 含义 | 判定标准 |
| --- | --- | --- |
| ✅ | 已完成 | 有工具/端点 + 有验证（单测或 HTTP 冒烟），且口径与 PRD 一致 |
| 🟡 | 部分完成 | 主链路可用，但 PRD 某半句没落地（边界写在备注列，不藏） |
| ⛔ | 未做 | 本仓不实现（缺外部基建）或确实没排上（进 §4 backlog） |

红线（与 AGENTS.md §3 一致）：**降级绝不 500、写动作恒送审、数据不出域、缺口如实标注不装完成**。

## 6. 维护规则

1. **改功能先改表**：本表是 PRD ↔ 实现的唯一对账面；新增/变更工具、端点、页面后必须回填 §2 对应行与 §4 状态。
2. **状态只三档**：✅ / 🟡 / ⛔，禁止「基本完成」；🟡 必须在备注列写清剩余半句。
3. **证据可核对**：证据列只写工具名 / 端点 / 单测 / 冒烟脚本名，不写主观描述。
4. **Backlog 顺序即施工顺序**：P0 → P1 → P2；每项完成后在本表 §5 记验证输出，并在 AGENTS.md §6 追加登记。
5. **不把后置写成完成**：缺外部基建的能力一律进「不做」并写明原因与解锁条件。
6. 与 `AGENTS.md` §6（待办登记）、`README.md`（功能表）口径一致；三者冲突时以本表 + PRD 为准并当场修正。
