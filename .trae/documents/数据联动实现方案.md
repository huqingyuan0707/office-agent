# office-agent 数据联动实现方案（M0/M1 地基 + M2 拉取①）

## Context

`office-agent` 已作为独立开源仓库落盘（remote `git@github.com:huqingyuan0707/office-agent.git`），但目前**只有 `apps/web` 一个 Vue3 单页前端和文档，后端完全不存在**（`packages/` 为空）。前端 `apps/web/src/api.ts:7` 期待 `http://127.0.0.1:8200` 上的 `/auth/login|/tools|/tools/invoke|/tasks|/approvals`，无处可连。

同时，`docs/office-agent仓库骨架与内核提取方案.md` §7 定义的「两仓库数据联动」在两侧都是零实现：电商项目 `backend/` 下 grep `office-agent|svc-office|X-On-Behalf-Of|tools-ecommerce` 无任何命中。

本次目标：**把联动落到实处并端到端可验证** —— 在 office-agent 建出联动必需的宿主（领域无关内核 + FastAPI 壳），并打通 §7 模式①「拉取」（office → 电商），使一次工具调用能真实取到电商数据、带溯源、trace 贯穿。模式②回流（写动作 + 幂等键透传）本次只留结构位，不实现。

已确认的三项决策：
1. 范围：`packages/core` + `packages/server` + 联动层，一次到位；
2. 信封：对齐电商 `{code,msg,data,trace_id}`，同步改前端；
3. 边界：两个仓库都改，先做拉取①。

## 关键事实（已核实，方案依赖）

- 电商侧 `app/core/middleware.py:35` 的 `TraceMiddleware` **已支持入站 `X-Trace-Id` 透传**（`Headers(scope).get("x-trace-id", uuid...)`），trace 贯穿无需新造；响应体自动补 `trace_id`。
- 电商侧信封与错误码：`app/core/responses.py:15-25` 的 `ok()/fail()`；`app/core/exceptions.py:11-45` 的 `ErrorCode`（1001 参数 / 1002 未登录 / 1003 无权限 / 4005 工具不存在 / 4006 Scope 拒 / 4007 熔断 / 4008 调用失败）。
- 电商侧内核可原样迁：`modules/agent/contracts.py`（`ToolSpec`/`ToolContext`/`validate_args`/`TRANSITIONS`）、`registry.py`、`policy.py`（`ensure_allowed` 抛 4006）、`executor.py`（超时/退避重试/熔断/全量审计，`call()` 为唯一入口）。
- 电商侧连接器 `modules/agent/connectors.py` 的 6 个工具**不是裸 REST**：`logistics.query` 要先从订单解析运单号、`stock.query` 要按尺码过滤、`coupon.query` 有 active 过滤。**因此上游出口必须复用 `executor.call`，而不是让 office-agent 直调各业务 REST 端点**（否则口径在第二处复制）。
- 电商侧 RBAC：`app/core/rbac.py:39-47` `require_perm` 是「角色即权限」（`roles` 里既放域角色也放权限令牌）；`policy.check` 经 `governance.has_scope(roles, scope)` 判 Scope。服务账号的 `roles` 必须显式包含 `order:read/stock:read/promo:read/kb:read`。
- 电商侧 JWT：`app/core/security.py` `issue_token()` 带 `sub/tenant/roles/iat/exp/jti`。
- 电商侧 `Idempotency-Key` 目前只在 `endpoints/promos.py` 用到，**没有全局幂等落库** —— 本次拉取①不涉及（只读不需要幂等），回流②时再定。
- 可迁模型：`app/db/models_foundation.py:45-77` 的 `Task`（含 `checkpoint`）与 `ToolCall`（`trace_id/tenant/username/name/args/result/latency_ms`）。
- 电商侧工程基线：`backend/pyproject.toml` ruff（line-length 100、target py311、max-complexity 15）、pytest（`asyncio_mode=auto`、`--basetemp=.pytest-tmp`、markers `smoke/slow`）、coverage `fail_under=70`。
- office-agent 现状：`apps/web` 是**自研最小单页**，非电商 `frontend/` 的拷贝（后者是带 router 的多页应用，用 `{code,msg,data}` 信封）。

## 联动契约（本方案的核心，实施按此执行）

### 出站请求（office-agent → 电商），唯一出口 `packages/core/.../linkage/provider.py`

| 项 | 值 | 依据 |
|---|---|---|
| 方法/路径 | `POST {base}/api/v1/agent-gateway/invoke` | 新增上游出口，复用 `executor.call` |
| 体 | `{"tool": "<上游工具名>", "args": {...}}` | 工具名 + 入参原样透传 |
| `Authorization` | `Bearer <服务账号 JWT>`（只走环境变量） | §7.3 凭据红线 |
| `X-Trace-Id` | office 侧本次调用的 trace_id | §7.3 trace 贯穿；电商 `TraceMiddleware` 已认 |
| `X-On-Behalf-Of` | 真实用户名（审批留痕不断链） | §7.3 身份透传 |
| `X-Office-Agent` | `office-agent/<version>` | 上游可识别调用方，便于治理 |
| 幂等键 | 本次不发送（只读） | 模式①范围 |

### 溯源包装（§7.2 模式①硬要求）

联动层在**收到上游响应时**生成，不为假数据编造：

```json
"provenance": {
  "provider_id": "ecommerce",
  "source_endpoint": "POST http://<upstream>/api/v1/agent-gateway/invoke",
  "tool": "order.query",
  "fetched_at": "2026-09-20T10:00:00+08:00",
  "upstream_trace_id": "<上游信封回传的 trace_id>"
}
```

`source_endpoint`/`fetched_at` **由联动层实测填写**（不是上游或工具声明里写死的值），这是「数值一致率 ≥99%」红线的校验依据。

### 错误映射

- 上游 `code == 0` → 取 `data`；
- 上游 4xxx 业务码（4005/4006/4007/4008 等）→ **原码上抛** `BusinessError`，前端错误表可分支；
- 上游 5xxx 或网络/超时 → 转 `ErrorCode.UPSTREAM_FAILED(5001)`，附上游 msg（不泄露堆栈）；
- 非幂等工具仍恒只调 1 次（红线跟随远程调用）。

## 实施步骤

### 一、office-agent：`packages/core`（领域无关内核）

按 `docs/office-agent仓库骨架与内核提取方案.md` §3 映射表提取，来源为电商 `backend/app/modules/agent/`：

1. `packages/core/pyproject.toml`（可独立 `pip install -e`）、`office_agent_core/__init__.py` 公开 API 重导出。
2. `errors.py`：迁 `core/exceptions.py` 的 `ErrorCode`/`BusinessError`（错误码号段保留，新增 `UPSTREAM_FAILED=5001` 已在电商侧存在，直接沿用）。
3. `contracts.py`：迁状态机白名单、`ToolContext`、`validate_args`（中文报错保留）；`ToolSpec` 新增联动插入点 ——
   ```python
   @dataclass(frozen=True)
   class RemoteBinding:
       provider_id: str   # 上游提供方标识，如 "ecommerce"
       tool: str          # 上游工具名，如 "order.query"
   ```
   `ToolSpec.remote: RemoteBinding | None = None`。其余字段（`idempotent/requires_approval/approval_action/timeout_seconds/max_retries`）原样保留。
4. `registry.py` / `policy.py`：原样迁（`spec_to_dict` 增加 `remote` 的 `provider_id/tool` 只读投影，不含凭据）。
5. `executor.py`：原样迁 `_Breaker`/重试/审计主链，**唯一改动**是 `_invoke_once` 分派：`spec.remote` 为空走本地 handler，非空走 `linkage.ProviderRegistry` 取对应 provider 调用，并把 `provenance` 挂到 `_outcome` 结果的同级字段。
6. `settings.py`：平迁 Settings 模式（`AGENT_TOOL_TIMEOUT_SECONDS/MAX_RETRIES/CIRCUIT_THRESHOLD/CIRCUIT_COOLDOWN_SECONDS/RETRY_BACKOFF_SECONDS` 同名同默认值），新增 `LINKAGE_PROVIDERS` 相关键（见步骤三）。
7. `observability.py`：精简迁 `record()`。

### 二、office-agent：联动层 `packages/core/office_agent_core/linkage/`

- `provider.py`：`RemoteToolProvider`（`provider_id/base_url/token/timeout`）；`invoke(binding, args, *, trace_id, on_behalf_of)` → 出站头按上表注入 → 解析上游信封 → 错误映射 → 返回 `(data, provenance)`。用 `httpx.AsyncClient`（测试用 `httpx.MockTransport` 注入，不打真实网络）。
- `registry.py`（联动内的 provider 注册表）：`register_provider(provider)` / `provider_of(provider_id)`；未注册 provider 时抛中文可操作的 `BusinessError`（不静默降级成假数据）。
- 凭据只从环境变量/Settings 读，绝不入库；provider 未配置时该远程工具**注册即失败并给中文提示**，不注册一个调不通的工具。

### 五、电商项目（`d:\多模态智能电商客服系统`）

1. **新增上游出口** `backend/app/api/v1/endpoints/agent_gateway.py`：

4. 迁移：若 `ToolCall` 新增字段，补 alembic 迁移（`backend/alembic/`）。
5. **红线**：本项目内核与既有测试**零回归**（`pytest` 全绿）；不改 `modules/agent/` 现有行为，仅新增端点与字段。

## 验证

1. **office-agent 单测**（`packages/core/tests`、`packages/server/tests`，pytest + `httpx.MockTransport` 假上游）：
   - 信封与 `trace_id` 注入（含 `X-Trace-Id` 入站沿用）；
   - Scope 不命中 → 4006；非幂等工具恒 1 次；连续失败 → 4007 熔断；
   - 联动层：出站头三件套齐全、`provenance.source_endpoint/fetched_at` 实测正确、上游 4xxx 原码上抛、上游 5xxx 转 5001、网络异常不 500 兜底。
2. **电商侧回归**：`cd backend && pytest` 全绿（内核零回归红线）+ `ruff check`。
3. **端到端**：起电商后端 → 起 office-agent（8200）→ 前端登录 → 调 `order.query` → 断言：结果数值与电商 `GET /api/v1/orders/{id}` 一致；`provenance.source_endpoint` 指向 `agent-gateway/invoke`；**同一 `trace_id` 在电商 `tool_calls` 审计表可查到**（跨系统一条线）。
4. **领域无关性门禁**：`grep -riE "finance|purchase|risk|sku|订单|电商" packages/` 零命中（`plugins/` 与 `docs/` 允许）。

## 风险与红线

- **内核双份漂移**：并行期 office-agent 侧内核**只做领域无关化，不新增功能**；任何内核改动先落电商项目再移植（ADR-0003 缓解措施）。
- **主包纯度**：`packages/` 严禁出现任何「if 电商」分支；电商耦合只允许存在于 `plugins/tools-ecommerce`。
- **防伪造**：`X-On-Behalf-Of` 必须与服务账号白名单绑定，否则等同把审计发起人交给调用方随便填。
- **不编造数据**：provider 未配置/上游不可达时，工具必须报错（转 5001），**绝不返回演示假数据**顶替，否则溯源与数值一致率失去意义。
- 上游业务码直传与 5xxx 转 5001 的边界在实施中固化到联动层单测，避免各工具各写一套。
